    poot repo · website

    A from-scratch LLM inference engine with graph tracing, kernel fusion, and multiple GPU backends.

    rust · llm inference · graph ir · wgpu · rocm · cuda
    • Forward pass traced once into a backend-neutral graph of primitive tensor ops, not opaque hand-written kernels.
    • Fused regions get kernels generated for them, while imported Rust kernels cover the shapes the generator does not (decode GEMV, flash fallback, gathers).
    • GPU dispatch sequence captured once and replayed per token (CUDA graph replay, cached wgpu re-encode), to cut launch overhead rather than compute.
    • Kernels written as real Rust #[kernel] functions lowered to SPIR-V/PTX/AMDGPU, with no cuBLAS or cuDNN.
    • Models are a Model trait plus a family registry: each architecture traces its own graph from a GGUF or safetensors checkpoint, with GPTQ/AWQ packed quantization kept resident.
    • One executor contract shared by the wgpu, ROCm and PTX backends, each checked against a CPU oracle.
    • Serving capabilities: an OpenAI-compatible HTTP API with embeddings, reranking, LoRA adapter management and metrics; text generation is being reconnected to the new single-sequence driver.

    ntfs-reader repo

    Fast in-memory scans of the NTFS master file table and a reader for the USN change journal.

    rust · windows · ntfs · mft · usn journal · filesystems
    • $MFT read straight off the raw volume into memory and parsed in one pass, not through Windows file-enumeration APIs.
    • Full-volume iteration with resolved paths in 3.9s, down from 12.3s uncached.
    • USN change journal read live, with event-mask filtering and a choice of start position (beginning, next, or a specific USN).
    • Renames tracked across journal events by matching the new name back to the old path from an in-memory history.
    • Deleted files supported: resolve their old paths, read their data back, and check whether it survived.
    • Memory-bounded modes for huge volumes: stream the table in chunks, load a compact form that uses 30 to 70 percent less memory, or cap the path cache.

    jevmon repo

    A process monitor for Linux workstations that run agent swarms. A decision model judges every process launch.

    python · rust · jev · laya · decision models · fine-tuning
    • Watches process launches straight from /proc; the code only builds a bounded, sanitized context for each one, and a small decision model gives the verdict. No hardcoded rules, scores or name lists.
    • Runs on the iGPU of a Strix Halo box: about 50 ms per context and at most two CPU cores, roughly 12 times faster than eight cores on the CPU.
    • Decisions are memoised per distinct situation, with a bounded queue and batched judging, so it keeps up with a busy build box.
    • A systemd user daemon with a Unix socket, and a Ratatui terminal client that follows the tail without ever moving your selection.
    • Every verdict is stored with its context as training data. A rootless-container lab generates labelled scenarios, split by scenario family. On held-out families a head over the frozen encoder reaches 0.68 macro-F1 against 0.21 for always answering routine; zero-shot Laya reaches 0.31 and full fine-tuning 0.56. Runs are tracked in Trackio.

    vuldir repo

    A unified rendering API for Vulkan and DirectX 12, built without third-party libraries.

    c++ · cmake · graphics · vulkan · directx 12 · hlsl
    • One bindless API over Vulkan 1.3 and DirectX 12, omitting either backend's native binding model entirely.
    • Device-owned descriptor heaps for stable resource indices that mean the same thing on both backends.
    • Resource state is tracked virtually while recording and published atomically on submit, so contexts record and submit concurrently.
    • Resource management, math, and PNG/HDR/JSON/glTF loaders are all from scratch, no third-party rendering libraries.

    combeanie repo · website

    A simulation-first robotics system for vision-guided beverage restocking in refrigerated shelves.

    c++ · python · ros 2 · gazebo · moveit 2 · robotics
    • Deterministic pipeline: state machine, world-state validation, geometric grasp/placement, MoveIt planning, then execution.
    • Learned components as optional adapters that can only select among already-authorized primitives, never bypass planning or command joints.
    • Success verified against world state, not self-report; an unproven run stopped safely, with the reason stated.
    • Autonomous restocking campaign: shelf and tray surveyed, deficits worked out, and transfers chosen and repeated until no compatible pair is left.
    • Lane routing that scores a real cost across compatible lanes, avoiding occupied ones and ones obstructed by something overlapping.
    • Obstacles absent from every model and scenario file changing what may be executed; execution refused, joints unmoved, when scene geometry is stale.
    • Seeded, byte-deterministic scenario replay for reproducing a specific failure exactly.
